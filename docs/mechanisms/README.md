# Mechanism documentation standard

## EN

This section follows the five standards below. Each declared mechanism changes with its owning code and distinguishes verified behavior from hypotheses.

## RU

Раздел следует пяти правилам ниже: описывает существующий механизм, меняется вместе с кодом, хранит контракты/ограничения/проверки и различает факты от гипотез. Индекс механизмов находится в config, а не дублируется здесь.

## Boundary
Verified game bindings, supported build and process identity. / Проверенные привязки к игре, сборке и процессу.

## Shape
Each mechanism has Purpose, Operation, Limits and Verification. RU/EN share one document; addresses have evidence and contracts.

## Update trigger
Change this mechanism's document whenever its declared include/test paths change. Decisions belong in ADRs if introduced; frozen research stays in the knowledge repository.

## Exclusions
No copied game binaries, plugin algorithms, deployment runbooks or speculative signatures. README/AGENTS are onboarding/instructions, not mechanism indexes.

## Acceptance criteria
Links resolve, current code matches the contract, evidence levels are explicit, native checks and docs-check pass.
